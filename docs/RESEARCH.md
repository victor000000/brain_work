## Scope and objectives

Simulation inputs are PV/options numeric values plus legitimate grouping fields. Research sources may cover all categories. A model output described as OTHER is not made PV by using a price-style formula; likewise an original macro/risk/news template needs explicit separate review before any permitted adaptation.

The full objective remains: find native-accepted alphas, correct real syntax/template defects, explore existing/community/generated templates across cells, improve actual CAP and Selected CAP, and reach platform-verified Expert. The user explicitly resumed it on October 23, 2026 (Asia/Shanghai).

## Read an idea before writing a template

Record the economic question, source author/date/URL, complete available contents, field definitions, expected direction, mechanism and control. Separate what the source claims from what this account has measured.

Check exact native category, type, units, maturity, timing, coverage and operator availability. For example, the saved entropy source uses operators absent from the current account's native operator list; a supported dispersion experiment is a different hypothesis, not an entropy reproduction.

Missing data is not zero. Integer sentinels, zero denominators, stale values and GROUP labels require explicit semantics. Do not add arbitrary epsilon constants or substitute unrelated fields to make a template parse.

## Finite experiment protocol

1. State one question and a bounded comparison. Choose economically justified fields/settings and controls before looking at results.
2. Freeze literal expressions, full settings, template tags and source/preflight hashes.
3. Deduplicate against retained outcomes, plan/claim receipts, expression ledger and protected uncertain payloads. State any gaps; a retained-file scan is not full live-DB history or semantic equivalence proof.
4. Validate exact-cell fields, operator scope, syntax, types and units.
5. Publish one immutable request through the sole writer during an authorized run.
6. Capture native parent/child/alpha IDs and verify exact expression/settings identity.
7. Analyze all planned cases, including failures. Do not silently report only winners or repeat a POST after an observation timeout.
8. Close a failed fixed comparison rather than optimizing an unbounded parameter grid. Any new mechanism needs a separately justified plan.

There is no fixed30-minute analysis gate. Analyze when completed evidence can change the next decision.
